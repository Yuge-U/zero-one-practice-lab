## 1. 今回使えるようになった機能

「保存した練習」の一覧、または練習詳細に「コピーして新規作成」を追加しました。
操作：保存した練習 → コピーして新規作成 → 練習名・人数・時間・メニュー・条件などを変更 → 端末に保存。
コピーを開いただけではDBに新規登録せず、保存時に新しい計画IDで登録します。明細IDも新しくします。
元の練習計画、元の実績、振り返り、タイマーは変更しません。コピー先に実績・振り返り・経過時間を引き継ぎません。
用語・作戦図・ドリル・Variationの固定版は保持し、コピー先の条件を変えた場合だけ新しい条件版として記録します。
「この計画を編集」は同じ計画の新しい版を保存する操作であり、別計画を作るコピーとは区別しています。
既存の練習項目単位の「次の計画に追加」も維持し、最初の空白項目が残って保存を妨げないようにしました。

## 2. 保存操作とUI

保存前の未入力・数値範囲・時間超過を、保存ボタンの近くに具体的な理由付きで表示します。入力を消さず、該当欄を強調します。
保存中・保存完了・未保存の変更を表示し、保存中の二重操作を防ぎます。変更なしの保存直後の連打では計画や改訂を増やしません。
Variation名は空欄なら「基本条件」を使います。作戦図は任意です。
ユーザーが承認したバスケットボールの01＋上向き矢印アイコンを、ヘッダー、ブラウザアイコン、manifest、Apple touch iconへ組み込みました。
ZERO ONEの濃色ヘッダー、明るいカード、PRACTICEの緑系アクセントと組版へ画面を更新しました。

**以前報告されたユーザーのiPhoneの保存失敗について、その物理端末での原因は確定していません。今回確認したのは改善後コードの正常保存・コピーと、入力条件エラーが明示される動作です。**

## 4. 旧データの保全と更新方法

同一URL・同一プロファイルで旧0.3.2に計画と振り返りを保存し、未送信2件を含むバックアップを取得しました。
通常のService Worker更新で1.0.0の事前取得・有効化を実応答から確認し、ブラウザ全体を再起動しました。
更新前後で `scope / operations / objects / pending / acknowledged` が完全一致。さらに旧計画をコピーして保存し、元の2操作が変わっていないことを確認しました。
試験のためにDBを初期化、サイトデータを削除、Service Workerを登録解除、保存パスを変更することはしていません。

URL中の`lab`、OPFSの `/.zero-one-browser-lab-v02/`、`/core.db`、ゲストと本人の分離キー、OneDriveの `ZERO_ONE_PRACTICE_LAB_V02` は互換性維持のため変更していません。
古い版が表示される場合は、入力を保存し、新しい版の準備案内を確認後、このアプリのタブをすべて閉じて開き直してください。ヘッダーまたはフッターに1.0.0と表示されることを確認します。
**更新のためにSafariのWebサイトデータを削除しないでください。端末内の記録を失うおそれがあります。記録は別の保存先にもバックアップしてください。**

## 5. 試験途中で修正した検証コード

最初のR09はコピー元の非同期読込・描画前にタイトルを判定して失敗しました。期待タイトル・記録数は変えず、実際の編集画面の表示完了を待つよう修正しました。
追加した更新試験は、更新待機中にブラウザプロセスを閉じるタイミングや非同期準備判定が適切でない失敗を起こしました。
最終版は最大30秒の明示的な非同期待機でService Workerの版と事前取得結果を取得し、アプリタブを閉じて正常な有効化を確認した後、ブラウザプロセス全体の再起動を別に検査しています。
期待する1.0.0、原本や未送信データの完全一致条件を緩めず、失敗した機能試験の自動再試行やskipで合格にしていません。過去の失敗結果は保持しました。
以前のWebKit `setOffline(true)` の診断問題も別です。配信サーバー到達不能は機内モードや `navigator.onLine=false` と同じ条件ではありません。
